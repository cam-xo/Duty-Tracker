What this tool does & doesn't do
  • Calculations follow the FDP, cumulative duty/flight time, LNO and standby limits set out in your FMS manual (based on CAO 48.1 Appendix 4B).
  • How an FDP is measured (10.6, 10.8, 10.10): each FDP entry is a task. The FDP itself starts at the first tasking and runs until the end of its last task, and every task stays in the same FDP until a real off-duty period separates them — standby is not off duty (1.3.1), and 10.10 requires an off-duty period after a call-out FDP before another FDP can start. So the time between tasks counts as FDP time, and a rest of 2+ hours extends the limit instead (10.8.1 caps "the FDP period including the rest period" at 16h; Tables 7 and 8 both measure the extended limit from the original start with the rest inside it). The limit is Table 6 by the first tasking time, plus split duty rest and any extension, less NFD in the 8 hours before the FDP started, capped at 16h.
  • Split duty rest is calculated automatically: any gap of at least 2 consecutive hours between tasks qualifies, measured from the end of the task (which already includes the 30 min after landing, per 10.8.1). Standby counts as rest — it is free of all duties with sleeping accommodation — but NFD does not, so an NFD splits a gap into shorter pieces. It is not applied to an increased FDP, per 10.6.1. Per 10.8.1's second condition, the remaining portion after the most recent qualifying rest is also capped at a fresh Table 6 lookup at the resumption time.
  • Mandatory rest bands on the Time Line now cover two separate triggers per 10.5, taking whichever is larger (not additive): a KSS score of 7 gives a fixed 3h rest; a KSS score of 8 or 9 gives the Table 10 base (8h/10h by completion time) — the manual's own reference for KSS>=8 ("Minimum ODP as per Table 4") is a documented error, since Table 4 is just the descriptive 1-9 scale with no ODP data, so Table 10 is used instead. Separately, any FDP that actually needed an extension, was increased, or organically ran past 12h gets the full Table 10 formula (base + extension component), same as 10.12.3. Each band is anchored to that specific task's own end and flags a conflict if the containing standby is still logged as running into the rest window, or if anything else starts during it.
  • Conservative assumption: within that rest gap, only the portion falling between 2100–0600 is treated as genuine sleeping accommodation (full credit, per Table 7) — it's unrealistic to assume someone actually sleeps during the day even though sleeping accommodation is available. The portion falling 0600–2100 is treated as resting accommodation only (half credit, capped at 2 hours total, per Table 8). The full raw gap (unweighted) is still what counts at 50% toward cumulative duty per Table 12.
  • The 40-vs-60-hour 7-day duty cap checks for a 36+ hour off-duty gap that fully contains at least 2 local nights (an 8+ hour break covering 2200–0500), based on your rosters being in a single time zone.
  • Late Night Operations are counted once per local night regardless of how many FDPs occurred, per the note under 10.13.
  • Cumulative duty windows clip entries to the window boundary and merge overlapping entries, so a duty straddling the 7- or 14-day cutoff counts only for the portion inside it.
  • The Time Line's "required rest" band only follows a rostered Standby period, anchored at the later of the standby's own end or the end of any NFD/FDP that started during it (Table 10 base by completion time, plus extra for an FDP running over 12 hrs, using an extension, or an increased FDP's 12-hour floor). Shortfalls show as a red hatched "rest conflict" band. Standalone FDPs with no enclosing standby don't get a rest band on the Time Line.
  • Flight Time (Shift) sums flight time across every FDP overlapping the relevant standby period (today's ongoing or most recently finished one; on a past day, whichever standby's end falls on that date), or the calendar day's FDPs if no standby applies — same day-resolution rules as LIVE/CURRENT/PAST FDP. The 10h/12h shown as its "max" is the per-FDP flight time limit (10.6) shown purely as a visual size reference — there's no actual regulatory cap on total flight time per shift, so this tile can legitimately show "over" without that meaning any rule was broken.
  • The Off-Duty Period tile in Live Status checks the rest taken before the most recent FDP or standby as of the day being viewed (not just standby periods, unlike the Time Line's per-standby view) — the two are worth reading together rather than expecting them to always agree. It only ever looks at the gap immediately preceding what's most recent for the selected day; it does not surface older unresolved shortfalls from further back in your history.
  • Preceding Rest (10.12.2) checks whether at least one qualifying off-duty period occurred somewhere in the trailing 14 days (36h including 2 local nights, Table 9) or, failing that, the trailing 21 days (72h including 3 local nights). Live mode checks as if you were starting a new duty right now. Historic and Future modes both check against whatever duty starts on the displayed day — a standby if one exists, otherwise the earliest FDP (e.g. a training/sim day logged without a standby) — if neither has been entered for that day, the check simply doesn't run, since there's nothing to anchor it to.
  • Cumulative Fatigue Recovery (10.12.1) is triggered if, in the trailing 7 days, you've had 3+ late night FDPs or used an increased FDP — once triggered, a 36h/2-local-night break is owed until one has been taken (reuses the same 36h/2-night definition as the 7-day 40h/60h cumulative duty cap decision). Shows "Not triggered" when neither condition applies.
  • The Duty tile's maximum is a local convention, not a rule from the manual: Table 6 is defined against FDP start time, and this applies it to the standby start time instead. Treat it as a rough reference only.
  • A KSS score of 7 recorded at either the start or end of an FDP adds a mandatory 3-hour rest (10.5) shown above the line on the Time Line, immediately after that task. Any NFD or FDP starting during that window is flagged as a conflict, same as the other rest-conflict bands.
  • The reduction of a calculated off-duty period to 12 hours (10.12.3) is not modelled.
  • The orange marker line on today's Time Line shows the max FDP end time for the FDP a tasking right now would fall into — which continues the current FDP if no off-duty period has been taken since its last task, or starts a fresh one if it has. The red line is simply the current time. Yellow extension-limit lines only appear when an actual open FDP has an extension type selected on it — they're not shown as a generic "what's available" hint.
  • An FDP logged with "Task still in progress" ticked has no end time yet — its duration, timeline band, and all totals stay live and keep growing until you edit it to add the actual end time. The "Must land by" banner and the marker lines above both use this open entry as their reference the moment one exists.
  • Per the FDP definition (ends 30 min after the last landing, if later than duty completion), the "Must land by" time shown is the true FDP max end minus 30 minutes — it's when the aircraft needs to be on the ground, not when the FDP clock itself expires. The true FDP max end time (which the 30 minutes is subtracted from) is shown in the banner's fine print, and the orange/yellow Time Line marker lines still show that true, unadjusted FDP max end.
  • The FDP tile, the orange marker line and the "Must land by" banner all use the same FDP calculation, so they agree. The Duty Log's per-row OK/Over status still uses the older per-task calculation and can differ where an FDP spans several tasks.
  • An open task left un-closed for more than 14 hours triggers a red warning on the banner and an "OPEN Xh ⚠" badge in the Duty Log, since an open FDP's duration keeps growing forever until closed and can otherwise silently distort every cumulative total. Having more than one open FDP at once also triggers its own warning listing them, since that's normally a data-entry slip.
  • Saving checks for entries added by another device since this one last loaded and preserves them, rather than blindly overwriting — protects against losing data if you're using this on two devices close together. It can't resolve two devices editing the exact same entry at the same moment (last save wins for that entry) — full conflict resolution would need real-time listeners.
  • Import Backup now also catches duplicates by matching type/date/start/end time, not just by ID — so re-importing the same duty under a freshly generated ID (e.g. from a different export) won't create a second copy.
  • Per 10.6, an FDP within a Day Shift standby (detected from the standby's notes containing "Day Shift") has its end capped at 2200 — the FDP tile, "Must land by" banner and orange marker line all reflect this. Select the Day Shift past 22:00 extension option once Duty Officer/Chief Pilot approval is given to lift the cap back to the normal calculated limit, shown as a yellow marker line.
  • This is a personal support tool. Air Maestro remains your company's official record per the FMS manual — always log there too.
  • Data is stored privately to your own account in Firebase — not shared with anyone else.
  • Use Export Backup periodically to save your entries to a file, and Import Backup to restore them — this protects you if data ever fails to carry over when this tool is updated.
